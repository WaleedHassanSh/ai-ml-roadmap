## Practice Rules

For every problem:

1. Read the problem carefully before coding.
2. Write at least one manual example.
3. Trace the logic by hand.
4. Start with a simple brute-force solution if needed.
5. Improve only after the simple version works.
6. Explain time and space complexity informally.
7. Add edge cases.
8. Keep the code readable.

## Time and Space Complexity Style

Complexity explanations should be simple and informal.

Example:

```text
Time Complexity: O(n)

The loop visits each element once, so the running time grows linearly with the input size.
```

Example:

```text
Space Complexity: O(1)

The solution only uses a few variables, so extra memory does not grow with the input size.
```
